## Initial findings (resolution below)
- A1 CONFIRMED by routing analysis, high: deployed demo web omits /ticket-email/* rewrite. Delivery page POSTs those paths to public site origin; Caddy sends them to Next and no Next route matches, so purchase links and QR retrieval fail. Evidence apps/web/next.config.ts:18, apps/web/src/app/delivery/page.tsx:38,50, deploy/Caddyfile.demo:1, compose.demo.yml:115.
- A2 CONFIRMED by code path, high: ticket checkout allows multiple tickets; cancelTicket cancels one of a pending non-cart order and reduces its reservation but does not reduce order amount. Settlement counts every ticket including cancelled ones when incrementing quantitySold while only activating pending tickets. Customer can pay original total for fewer tickets; sold cache is overstated, and a subsequent purchase can make settlement violate the DB capacity check. Evidence apps/api/src/booking/booking.service.ts:617-626,740-775; packages/database/prisma/migrations/20260902023000_init_core_schema/migration.sql:437-438. Needs isolated DB reproduction including webhook reconciliation behavior.
- A3 CONFIRMED by code path, high: paid table booking can be cancelled after admission; no used-ticket check, releases consumed allocations and sets booked table available while used tickets remain used. This allows a table with admitted guests to become saleable. Evidence apps/api/src/booking/booking.service.ts:794-814 and apps/api/src/tickets/tickets.service.ts:208-236. Requires non-cart booking and policy permitting cancellation. Verify UI access and isolated DB behavior.
- A4 SUSPECTED race, high: cancellation reads ticket/booking and order before taking order lock and uses stale data afterward. If scan or settlement commits while cancellation waits, it may overwrite used ticket with cancelled, use old payment state, or reopen a table. Different idempotency keys can race similarly. Evidence apps/api/src/booking/booking.service.ts:748-763,794-817; scan locks and rereads at apps/api/src/tickets/tickets.service.ts:186-196. Needs controlled concurrent PostgreSQL reproduction; check transaction isolation and constraints.
- A5 CONFIRMED by topology and code, medium: unauthenticated rate limits share the API's request.ip. Next rewrite proxies public auth through web, API does not configure Express trust proxy, so clients through the same web instance share the same IP bucket. 10 Telegram attempts or 30 other same-path attempts per minute block other users; see apps/api/src/auth/sensitive-rate.guard.ts:17-24, apps/api/src/main.ts:12-22, apps/web/next.config.ts:24-27, compose.demo.yml:69-70,115-125. Validate actual proxy socket topology under deployment; distributed edge limiting is separately documented as a deployment gate.
