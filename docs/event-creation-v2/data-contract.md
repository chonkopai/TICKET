# Event creation v2 contract — Batch 1

Version 2 aggregate and snapshot contracts live in `packages/shared-types/src/event-creation-v2.ts`. Existing contracts remain historical/compatibility types during expansion. New creation may not accept deposit fields. This file fixes names and invariants for Batches 2–3; endpoint implementation remains Batch 4/9.

## Authoritative relations

`Event` keeps its UUID, organizer and lifecycle. Add nullable `saleMode`, `currency`, `startsAt`, `endsAt`, `refundsAvailable`, and monotonic `revision`/`refundPolicyRevision`. UTC instants plus existing IANA `timezone` are canonical after consumer cutover. Legacy date/time, text, poster/gallery and deposit columns are temporary compatibility projections; they contract only in Batch 13. Unknown legacy ends remain null.

`EventContent(eventId, locale)` owns all localized event text, including source: title, summary, description, venueName, address, refundConditions; nullable fields support incomplete legacy/partial locales. Each row has revision, field metadata and management/provenance markers. `TicketTypeContent(ticketTypeId, locale)`, `TableContent(tableId, locale)`, `VenueRowContent(rowId, locale)` own localized stable inventory labels/descriptions. `HallTariff(id, venueLayoutId)` and `HallTariffContent(tariffId, locale)` preserve geometry tariff UUIDs. A tariff configures a price; the normalized sold TicketType/Table remains the canonical charge resource, retaining whole-table semantics. No amounts on content rows. Backfill never changes existing resource amounts.

`EventCreationDraft` is an incomplete JSON aggregate (`version:2`) with source locale, one selected mode and retained inactive forms, shared classification/schedule/refunds, five nullable media slots, roles/crops and partial text/metadata. Its row owns revision, optional user, hashed anonymous capability, expiry/state and unique result Event. No incomplete visitor Event or synthetic organizer. Draft hall format is version 3: geometry is shared, localized text belongs to tariff IDs and price is on tariffs; capacity comes from seats/zones, not duplicated on tariffs. Existing layout JSON versions stay historical until Batch 6 provides the persistence adapter.

`EventPublishIntent` binds a draft/revision/aggregate SHA-256 to an independent browser-cookie hash, expiry, consumption and result Event. Unique `(draftId, revision)` makes repeated Publish at the same revision converge; expired unconsumed intent can be renewed only by a new validated Publish action. Consumed intent/result is immutable. Unique draft result plus row locks is the event-creation idempotency boundary.

`MediaAsset` owns typed storage/processing metadata, originating draft and/or event scope. `EventMedia(eventId, assetId)` assigns one slot 0–4, gallery visibility, distinct singleton card/background flags and role-specific crops. Composite event/asset ownership FK rejects attaching an asset scoped to another event. Draft references are checked against locked draft/asset rows. Unique event/slot, event/asset and partial singleton-role indexes enforce row-local invariants; publication locks enforce maximum five uploads and exactly one ready card/background. One image may carry both roles. Unknown legacy media is never promoted to ready.

`LegacyEventSnapshot(eventId, fingerprint)` archives original source/target sections, media references and hall JSON without altering authoritative money. `EventBackfillCheckpoint` stores bounded/resumable cursor/version/count. Event `v2State`, legacy fingerprint and review reasons distinguish legacy, reconciled, review and dirty aggregates. Legacy writers mark normalized aggregates dirty rather than silently leaving authoritative-looking stale rows.

## Validation and presentation

Every editor/API text field uses the same Unicode grapheme limits from the implementation brief. Draft parsing allows blank/missing localized fields but rejects overlimit input. A separate code-unit bound protects against enormous combining-mark payloads and reports an error rather than truncating. Editor integration must avoid enforcing mid-composition IME state; validate committed composition/paste and API saves. Migrated legacy text is preserved even when overlength, with review flags; it never passes publish validation silently.

`publishReadyDraftSchema(serverContext)` validates source completeness, selected resources, finite capacity, free zero charge, at least one active positive paid type, paid refund conditions, classification, schedule, supported adapter currency and scoped ready media metadata/limits. Inactive forms survive but do not contribute sales. Optional translations do not block source publication. Server reloads assets and currencies; client-supplied processing/ownership metadata is not evidence of readiness. Hall geometry uses the existing shared geometric constraints; publication requires used active tariffs, nonzero zones and sellable seats.

`localTimeCandidates` resolves venue wall times against IANA rules. Nonexistent local times fail; repeated times require explicit earlier/later selection. Start/end resolution rejects end ≤ start and supports explicit overnight end dates. Store UTC instants and zone, retain chosen occurrence in the draft. No automatic inferred legacy end.

Settlement amount parsing accepts plain nonnegative decimal strings at the configured currency exponent and uses BigInt arithmetic. Reject exponent notation, extra decimals, unsafe totals and mixed currencies; persist checked PostgreSQL Int minor units. KZT is the draft default but permitted currencies come from the selected server payment adapter, never an arbitrary client dropdown. Currency changes require explicit relabel acknowledgement and do not convert amounts. Buyer display conversion stays separate.

Media has exactly five nullable positions; deletion clears its position, reorder moves references without changing roles, and gallery skips holes. `mediaFrame` computes cover/focal/zoom framing for ordinary 8:5, actual featured frame, desktop/mobile backgrounds without cropping originals. Upload quotas/decoded validation/private transport/derivatives are Batch 5 work. No video may be card; public backgrounds mute, play inline, pause and fall back for reduced motion/data saving/failure; gallery videos use controls.

Locales are `ru/en/kk`; source is website locale at creation, else `ru`, immutable across content-tab changes. Empty target fields stay empty. Metadata keys are event field names, `sale.<stableId>.<field>`, or `media.<assetId>.caption`: SHA-256 source field hash, origin, reviewed/stale and field revision. Translation requests bind source and target revisions/hashes; default fills only missing fields, manual replacement needs consent, proposals over limits need editing. Public selection uses one complete current locale across relevant required fields and selected sale labels, otherwise labelled source fallback; no per-field mixed-language fallback. Provider configuration/live verification is Batch 7.

## HTTP, concurrency and recovery

All `/api/creation-drafts` traffic uses same-origin proxy and credentials cookies. Anonymous cookie: 256-bit random capability, only SHA-256 persisted, Secure HttpOnly SameSite=Lax, scoped path; never URL/browser storage/logs. Bind mutation to allowed Origin plus CSRF token bound to cookie/draft; no missing-Origin bypass for browser writes. JWT/organizer APIs retain guards. Uniform not-found errors prevent guessed IDs from revealing ownership.

Create/read/partial-update/validate/delete are separate capability endpoints. Partial-update merges supplied fields into the server aggregate (arrays replace atomically), then validates; absent values never erase other locales/inactive forms. Source locale and owner/state/result are immutable by payload. Save uses expected revision (`If-Match` or explicit revision), locks/rechecks and increments once. Conflict is 409 with current revision; a client must fetch/reconcile rather than last-write-wins. Media/hall/translation and Publish flush autosave first. Quotas are scoped to browser/account/draft, bounded by body/field/upload limits.

Anonymous lifetime: 30 days, owned lifetime: 90 days; actual policy constants are shared. Publish intent: 15 minutes and exact revision/hash. Expiry or changed revision requires review/new Publish. Cleanup eligibility starts after a seven-day recovery grace and only after commit/reference recheck; never collect publishing/published/historical references. Claim requires verified authenticated principal **and** matching capability; revoke anonymous hash/access atomically after owner assignment. Authentication cancellation/failure leaves server draft intact. Local browser text recovery is secondary, never a capability store.

Valid anonymous Publish creates an intent after saving/validation, then safe allowlisted auth continuation. Verified callback invokes protected claim/enrollment/publication POST; GET/query hydration alone cannot publish. `ORGANIZER_REQUIRES_APPROVAL` preserves draft and returns actual policy requirement. Lock draft, intent, Event/resources/media in stable order and consume result once with audit/outbox. Provider calls/uploads/translation stay outside transactions. Replay/lost response returns existing result. Success `/organizer/events/:id/edit?published=1&lang=…`; refresh browser role and prevent hydration republish.

Errors include 404 capability not found/revoked; 410 expired; 403 Origin/CSRF/approval requirement; 409 revision/intent/source-target conflict; 422 source/mode/schedule/currency/media validation; 429 quotas; 503 unavailable providers. Shared `draftApiErrorSchema` names stable codes. Do not log cookies, capability hashes as identities, credentials, uploaded content or provider request secrets.

## Purchase/refund history and migration

New `purchaseSnapshotV2Schema` freezes charged line unit/quantity/total/currency, actual locale/content/schedule/venue, accepted refund conditions/availability/locale/revision/time and free cancellation. `refundSnapshotV2Schema` identifies original order/payment and accepted policy revision; free cancellation has null payment/zero monetary amount. Free text does not implement automatic refund arithmetic. Keep exceptional organizer/provider-approved refunds.

`parseHistoricalPurchaseSnapshot` validates explicitly versioned v2, refuses unknown explicit versions and returns legacy missing/partial/deposit JSON unchanged. No default v2 policy, amount conversion, new snapshots or historical notifications are backfilled. Existing identity/inventory/QR/refund/delivery/analytics links and amounts remain unchanged.

Expand nullable fields/tables/indexes first. Compatibility flag `EVENT_CONTENT_V2_ENABLED` defaults false. Legacy writes invalidate normalized state under SQL triggers even from old binaries; normalized writes mirror still-required legacy columns inside the same transaction. Reads use normalized complete reconciled content only when flag enabled, otherwise controlled legacy fallback. Backfill uses per-event locks, archival fingerprint and editor-managed row protection, bounded keyset cursor and dry-run default. Unresolved deposit/mixed modes/currencies/media/capacity/schedule/text/history exceptions remain review/legacy sales paths. Forward migrations only; applied files/checksums remain untouched.

Batch 1 gate: shared contract tests cover grapheme boundaries/partial locales, exact money/overflow, scoped media, schedule gaps/folds (including half-hour DST), selected mode, whole-locale fallback and versioned history. Later batch gates must verify implemented HTTP/storage/publication/checkout behavior rather than infer it from these contracts.
